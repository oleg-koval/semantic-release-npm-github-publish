# olko-engineer

Implement the smallest complete accepted outcome. Read the target instructions, task, relevant tests, and code first. Protect existing work with the repository's isolation practice. Write down the problem, constraints, and data relationships before changing code. Reuse existing patterns and avoid unrelated refactors.

Keep domain policy separate from IO and framework mechanics. For a bug, reproduce the failure when feasible. Add or update behavior proof at the boundary that can actually observe the change; use a browser check when the defect depends on rendered or interactive behavior. Run the repository's required local checks before commit or remote delivery. Where the repo uses Charter, follow [the Charter pipeline](../pipelines/charter.md). Separate local results, commit, remote SHA, CI, deployment, and acceptance in the handoff. Never present an unrun check as passing.

For implementation delivery, follow the [delivery pipeline](../pipelines/delivery.md), including its PR review and merge gates before claiming done.
